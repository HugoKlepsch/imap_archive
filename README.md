# IMAP archive

A read-only IMAP server holding a long-term archive of Gmail, so that mail can
be deleted from Gmail to free quota while staying searchable from Thunderbird
and a web UI on the home network.

It does not send mail and it does not receive mail. Nothing listens on the
public internet.

> **Once mail is deleted from Gmail, this is the only copy.** Every design
> decision here follows from that. See [docs/orientation.md](docs/orientation.md).

## Components

| Component | Role                                | Ports                            |
|-----------|-------------------------------------|----------------------------------|
| Dovecot   | IMAP server (read-only archive)     | 143, 993 (31143/31993 inside)    |
| lego      | ACME DNS-01 certificates via Linode | —                                |
| Roundcube | Web UI                              | 8083 on the host, behind Caddy   |
| mbsync    | Gmail → Maildir sync                | — (outbound IMAPS only)          |
| restic    | Encrypted offsite backup            | — (outbound HTTPS only)          |

Containers run under docker compose, with lifecycle managed by systemd units
generated by `create-systemd-service.sh`. Configuration and secrets live in
`.env.bash` (see `.env.bash.template`).

## Layout

```
compose/            docker compose service definitions
config/dovecot/     Dovecot configuration (committed)
config/roundcube/   Roundcube overrides (committed)
docs/               the documents above
scripts/            setup, sync, backup, restore, verification, alerting
generated_config/   generated units & password hash (gitignored)
nas_data_mnt/       CIFS mount: the mail itself (gitignored)
local_data_mnt/     local disk: indexes, control, certs (gitignored)
```

Storage is split deliberately: messages on the NAS, and everything Dovecot
locks or mmaps on local disk. SMB does not implement that locking correctly and
will corrupt Dovecot's index and control files. Do not move them.

## Status

All four components are written: Dovecot and TLS, the Roundcube web UI, the
mbsync pull from Gmail, and verification plus restic offsite backup. **None of
it has been deployed to the server yet** — follow
[docs/initial-setup.md](docs/initial-setup.md) from step 0.

**Nothing should be deleted from Gmail until the backup, restore and
verification scripts have all been run on the real archive and passed.** See
[docs/initial-setup.md](docs/initial-setup.md) step 13.

## Quick reference

```bash
sudo systemctl status imap-archive
sudo journalctl -u imap-archive -f
./scripts/gen-secrets.sh                 # after changing any credential
sudo ./scripts/renew-cert.sh             # certificate (also on a daily timer)
sudo ./scripts/sync-gmail.sh             # pull from Gmail (also on a daily timer)
sudo LIST=true ./scripts/sync-gmail.sh   # list Gmail folders, read-only
./scripts/backup.sh                      # offsite backup (also on a timer)
./scripts/check-backup.sh                # verify the backup really restores
./scripts/restore.sh                     # test restore to a scratch dir
FULL=true ./scripts/verify-archive.sh    # compare the archive against Gmail
./scripts/notify-discord.sh --test       # confirm alerting still works
```
